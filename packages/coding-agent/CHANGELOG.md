# Changelog

User-visible changes to `@ny4n/coding-agent`, the `nyan` CLI. `/changelog` shows this file, and Nyan shows the new sections once after an update. Releases are tagged `nyan-vX.Y.Z`.

## [Unreleased]

### Added

- The session-selection flags now work on durable sessions instead of routing the run to the legacy JSONL path: `--session <dir>`,
  `--session-id <id|prefix>`, `--session-dir <dir>`, `--name <name>`, `--fork <entry-id>`, `--resume`, and `--no-session`. An existing
  `.jsonl` file passed to `--session` still opens read-only through the compatibility route, and a session that cannot be opened prints one
  `Error:` line and exits 1 instead of a stack trace. `--fork` forks inside the same session, because a durable conversation cannot be copied
  into another session directory yet.

### Fixed

- The lines a session shows below the transcript no longer stay for the rest of the session. An extension failure, a
  command's answer, or a warning the runtime recorded now disappears on its own (10 s for an info line, 15 s for a
  warning, 30 s for an error), and at most the newest three are shown, so a long session no longer collects a growing
  block of old messages above the editor.

## [1.4.2] - 2026-10-21

### Fixed

- An extension's `before_agent_start` message or system prompt now reaches the request that carries the prompt that produced it. When a prompt was submitted while a run was in flight, its effects were missing from that request and appeared on the next run's first request instead.
- A `/fork` or `/clone` whose extension shutdown fails now still switches to the new conversation and reports the failure as a notice. Before, the session stayed on the old conversation and the already-committed fork could not be reached again.

## [1.4.1] - 2026-10-20

### Fixed

- The default interactive mode now completes what you type in the editor. Typing `/` opened nothing, and a slash command had to be spelled out in full. It now lists the commands that mode answers with their descriptions, completes the arguments of `/model` and `/thinking` and of extension commands, and completes `@` file paths from the working directory. `autocompleteMaxVisible` sets how many entries are shown, and `/settings` applies a change to it without a restart. `/import` and `/tree`, which this mode answers with the reason it cannot run them, are listed as unavailable rather than as the commands the legacy interface runs.

## [1.4.0] - 2026-10-20

### Breaking Changes

1.4.0 makes the durable Harness and its SQLite session store the default for interactive, print, JSON, and RPC sessions (Decision #17). These are the changes a 1.3.0 user meets. Each one says what to do about it.

- **Sessions are SQLite directories under `~/.nyan/agent/sessions-durable/`, and a session file from 1.3.0 is read-only.** A JSONL session is never migrated or appended to, so `--resume`, `--session <file>`, `--session-id`, `--fork`, `--session-dir`, and `--no-session` keep the compatibility route and its JSONL storage. `--continue` continues the current directory's newest durable session; a directory that has only JSONL sessions reopens the newest of those read-only, with the notice a resumed session prints; a directory with neither starts a new durable session, as 1.3.0 started a new one (Decision #32). The `sessionDir` setting and `NYAN_CODING_AGENT_SESSION_DIR` no longer choose where a new session is written, because the durable store's location is fixed; `--session-dir` still chooses where the JSONL store is. **What to do:** open work from 1.3.0 with `--resume` or `--session <file>` (both read-only), or start a new session; a project that relied on a shared `sessionDir` for new sessions gets one store per working directory instead. See [Sessions](docs/sessions.md) and [Session format](docs/session-format.md).
- **`--mode rpc`: a fork stays in the same session, and the tree is linear.** `fork` and `clone` create a new conversation inside the session and move the client to it, so `sessionId` and `sessionFile` do not change and the next prompts and events belong to the forked conversation; only a user message can be forked from. `get_tree` returns the active entry chain, which is linear, and `get_entries` reports entry ids as decimal strings with `parentId` chaining them in order, while a compaction entry's `tokensBefore` is an estimate. **What to do:** a client that assumed a fork wrote a new session file, or that rendered a tree with branches, must read the session and the returned chain instead. See [RPC](docs/rpc.md) and [JSON event stream](docs/json.md#durable-path).
- **Extension handlers see less on the default path (Decisions #23, #28, #29, #31).** `message_end` rewriting applies to assistant messages; a tool result is rewritten through `afterTool` and user input through the `input` event, and the `custom` role does not exist there. A turn that ends in error or abort runs no boundary hook, so `turn_end` and `agent_before_settle` do not fire for it. `messageEntryId` is absent for a turn whose final answer commits together with the boundary. A boundary draft cannot write a compaction entry or a head marker, and `session_before_compact` gets the durable cut: another `firstKeptEntryId` is refused. Drafts are proposals that durable validates: an edit of an assistant or tool-result entry, a compaction draft, and a draft that breaks tool-call pairing are refused with a diagnostic instead of being applied, and a crash before the turn's commit can make a boundary handler run twice. `session_before_tree` and `session_tree` are not emitted. `ctx.ui` offers `notify`, `setStatus`, `select`, `confirm`, and `input`; widgets, header and footer replacement, editor replacement, autocomplete, and custom components are not there yet. **What to do:** guard `message_end` rewrites by role, move input rewrites to `input`, expect a boundary handler to be idempotent, treat a refused draft as reported rather than applied, and drop the tree and UI work from an extension that must run on both paths. See [Extensions](docs/extensions.md).
- **The durable TUI, which is the default interactive mode, answers some commands differently.** `/tree` is not available because a durable conversation is linear (Decision #24). `/import <path>` is not available because a durable session is not a JSONL file; read a legacy session with `nyan --session <file>` or `nyan --resume` instead (Decision #34). `/model` opens a filterable list rather than the legacy picker, and the default model for new sessions is saved in `/settings` (Decision #36). `/bug` writes the report to a file and records no entry in the session. `/settings` still lists the settings only the legacy interface consumes, and changing them has no effect on a durable session (Decision #38). Display-only items are not ported yet: the theme file watcher, terminal progress, and the footer's git branch, cache hit rate, and 70% context-warning tier (Decision #37). Quitting does not print the command that resumes the session, because session selection on the command line covers the JSONL store only (Decision #25). **What to do:** use `/settings` for a default model, `nyan --resume` for a 1.3.0 session, and the legacy route for anything the table in [Slash commands](docs/slash-commands.md#durable-sessions) lists as different. See [TUI](docs/tui.md).
- **`ctrl+c` in the default interactive mode clears the editor and exits on the second press within 500 ms.** A single press used to end the session, so a run now needs two. **What to do:** press `ctrl+c` twice to quit, or `/quit`. See [Keybindings](docs/keybindings.md).

### Added

- Built-in `CLIProxyAPI` provider (`builtin:cliproxyapi`) supporting `/login CLIProxyAPI` and CLI `nyan login cliproxyapi` / `nyan auth login --provider cliproxyapi`. It discovers models from the proxy, provides declarative model limits and thinking level overrides, priority Fast mode (`/fast`), request pause gate (`/pause`, `/continue`), real token throughput reporting, and `/cpa-*` management commands. Existing `cliproxyapi.json`, overrides, cache, and auth credentials from `~/.nyan/agent` are loaded automatically.
- CLIProxyAPI telemetry: one record per request with time to first token, generation window, tokens per second, total time (excluding `/pause`), HTTP status, tokens, estimated cost, retries, and trace id, published on the `cliproxyapi:request` extension event. The 5 hour and weekly plan quota of the Codex and Claude accounts behind the proxy is read from the proxy's management API (`CLIPROXYAPI_MANAGEMENT_KEY`) or from `x-codex-*` and `anthropic-ratelimit-unified-*` response headers when the proxy runs with `passthrough-headers: true`, shown by the new `/cpa-quota`, and published on `cliproxyapi:quota`. Nyan stops sending a management key the proxy rejected and waits out the proxy's 30 minute ban. See [Providers](docs/providers.md#cliproxyapi).
- CLI login commands `nyan auth login [--provider <provider>] [--method <oauth|api_key>]` and `nyan login [provider]` to authenticate with providers directly from the terminal without entering interactive mode.
- An extension login prompt can require an answer with `onPrompt({ allowEmpty: false })`. The prompt is asked again instead of returning an empty string, and both `nyan login` and the interactive dialog honor it. `allowEmpty` defaults to true, and the manual authorization-code prompt requires an answer because an empty code can never be exchanged.
- In the standalone executable (Bun), Nyan prints a warning once at start-up when `NODE_OPTIONS` contains `--use-system-ca`: Bun and compiled Bun binaries do not read `NODE_OPTIONS`, so the operating system certificate store is not used. The warning names `NODE_USE_SYSTEM_CA=1`, `BUN_OPTIONS=--use-system-ca` and `NODE_EXTRA_CA_CERTS` as the ways that work. See [Environment variables](docs/environment-variables.md).
- `--mode rpc` on the durable session path now answers `clear_queue`, `get_entries`, `export_html`, `set_session_name`, `fork`, `clone`, `get_fork_messages`, and `get_tree`, and `get_state` reports `sessionName`. Entry ids are durable entry ids as decimal strings, `parentId` chains the entries linearly, and a compaction entry's `tokensBefore` is an estimate. A fork is a new conversation inside the same session: the session keeps its id and file, the client's next prompts and events belong to the forked conversation, `get_tree` returns the active entry chain, which is linear, and only a user message can be forked from. A durable session records its cwd and keeps its display name in `session.json` beside `session.sqlite`, so both survive a restart. `switch_session` opens an exact durable session directory, preserves the current session when the target is invalid or locked, emits the resumable `session_start` event, and rejects legacy JSONL files with a named read-only error. `bash` and `abort_bash` now execute through the durable environment, stream `bash_execution_update`, and record a `bashExecution` entry; `excludeFromContext` retains the result without adding it to model context. `abort_retry` now stops a retry that is waiting out its backoff: the wait ends at once and the turn ends with the error the last attempt failed on, as when retries run out, while aborting the turn still ends it as aborted; with no retry waiting the command succeeds and changes nothing.
- The durable TUI, the default interactive mode, now answers `/settings`, `/thinking`, `/scoped-models`, `/trust`, `/login`, `/logout`, `/reload`, and `/hotkeys` itself instead of sending them to the model. `/settings` is the same dialog the legacy interface shows, with a new **Default model** item for the model a new session starts with, and a change reaches the running session where this path has an equivalent: auto-compaction, steering and follow-up modes, per-model thinking overrides, theme, output and editor padding, image options, and the fullscreen scrollbar, copy-on-select, and wheel settings. `/thinking` sets a level from its argument or opens the level picker, `/scoped-models` limits the models `/model` lists and saves the set to `enabledModels`, `/trust` stores a project trust decision for later runs, `/login` and `/logout` run the same provider dialogs as the legacy interface, `/reload` reopens the session with freshly loaded extensions and keeps its transcript, and `/hotkeys` lists the keys this interface binds. `/tree` and `/import` answer with the reason they are not on this path: a durable conversation is linear, and a durable session is not a JSONL file.
- The default session path now keeps provider prompt caches warm. `cacheWarming` (`streaming` by default, or `idle`, or `off`) used to be accepted and ignored there, so a long tool turn or a paused session paid a full cache write for its next request. A refresh is the conversation's own request with a one-token output cap, keeping its model, messages, thinking level, provider session, and request transforms, so it writes the cache entry the next request reads; the extension `cache_warming_decision` event can veto it, and the refresh's spend is added to the conversation's usage ledger. Warming lives in memory only: a restart reopens the conversation and the next request starts a new one.
- `/share` and `/bug` work in the durable TUI. `/share` uploads the session's HTML export as a private gist through the GitHub CLI, and `/bug` asks the same questions as before and writes the same zip archive, including a summary written by the current model when the transcript is left out; the report's transcript is the durable session's own JSONL mapping. Both use the upload and archive code the legacy mode uses, so the options are the same on both paths.
- The durable TUI, the default interactive mode, now handles the editing keys the legacy interface handles: submitted lines, including commands, enter the prompt history that up and down browse; `ctrl+v` inserts copied file paths, the path of a pasted image written to the temporary directory, or copied text; `ctrl+g` edits the prompt in `externalEditor`; `alt+up` withdraws the queued messages and restores them above the editor's draft; `ctrl+p` and `shift+ctrl+p` cycle through the models `/scoped-models` keeps; `ctrl+z` suspends to the background; `ctrl+t` hides or shows thinking blocks and stores `hideThinkingBlock`; and extension shortcuts are dispatched to their handlers. `/hotkeys` lists these keys.
- A durable interactive session now shows the notices a legacy session showed at start: a new release and package updates with the command that applies them, the changelog sections newer than the last version run (once after an upgrade, reduced to one line by `collapseChangelog`), a crash the previous run recorded with a pointer to `/bug`, a project that is not trusted while it holds project resources, the resources that loaded unless `quietStartup` hides them, a resource the loader could not read, and a tmux keyboard setup that cannot carry modified keys. The terminal title is `Nyan - <session name> - <directory>` and follows `/name`. The footer shows the directory relative to your home, `(sub)` for a subscription-backed provider, `(auto)` while automatic compaction is on, the provider in front of the model when several are configured, and the physical model a virtual selection routed to as `→ model`.
- An extension that registers a provider whose key only resolves requests can declare it: `apiKeyResolveOnly` is part of the extension API's `ProviderConfig`, so nyan offers that provider's own login instead of an API-key method. The built-in CLIProxyAPI provider already behaved this way; it no longer has to cast its registration to say so.
### Changed

- The default session path now reads these resource flags: `--skill`, `--no-skills`, `--no-context-files`, `--system-prompt`, `--append-system-prompt`, `--no-extensions`, `--no-mcp`, `--no-themes`, `--no-prompt-templates`, `--approve`, and `--no-approve`. It loads skills, context files, prompt templates, extensions, and themes from the same places as the legacy path, puts `--system-prompt` and `--append-system-prompt` into the request, applies `--use-theme` in the interactive mode, reports invalid settings files, and registers the providers of extensions, so `--provider cliproxyapi` resolves. Extension commands and the five-method UI subset (`notify`, `setStatus`, `select`, `confirm`, and `input`) now work in the durable TUI; RPC forwards the same UI subset through its existing UI protocol, while JSON and print remain UI-less. Extension tools are connected for the `direct` and `model-only` exposures (see the next entry). Prompt templates expand before durable prompts in interactive, print, JSON, and RPC modes, and RPC `get_commands` reports them. `--session`, `--session-id`, `--resume`, `--fork`, `--session-dir`, `--no-session`, `--name`, `--tools`, `--models`, and `@file` also still use the legacy path.
- The durable path now offers the tools that extensions register to the model, with their `exposure`: `direct` and `model-only` tools are offered, and `tool_call` and `tool_result` handlers run on them. MCP servers configured with `"exposure": "direct"` in `mcp.json` connect before the first prompt. MCP tools with the default `codemode` exposure reach the model through codemode, and `deferred` tools through tool search, as the entry below describes.
- The default path now runs an extension's `context`, `before_agent_start`, `agent_end`, `agent_settled`, model-selection, boundary, stream, tool-update, and compaction handlers, and its session start and shutdown handlers. CLIProxyAPI's per-run usage summary and its quota poll happen after every run, including runs that ended without an answer, and its Fast tier and persisted pause setting apply to requests made there; before-agent-start message and system-prompt effects apply to the first request of the run. On the durable path, boundary drafts are validated before commit and invalid assistant/tool-result edits, compaction drafts, and mismatched compaction cuts are reported rather than silently applied; a handler may run again after recovery. The durable path also exposes a read-only session-manager facade over its conversation entries. Extension slash commands, including `/fast`, `/pause`, `/continue`, and `/cpa-*`, are available in the durable TUI and RPC modes.
- Codemode and tool search run on the default path while they are active, as on the legacy path: MCP servers whose tools are reachable only through codemode activate it, and a script calls those tools. Scripts keep the limit of two running at once. The `models` globals and `codemode.mode` `only` are not on this path yet.
- The default session path now runs an extension's `input` handlers for every prompt, steer, and follow-up in the TUI, print, JSON, and RPC modes, before skill commands and prompt templates expand; a `handled` result submits nothing, and RPC answers `disposition: "handled"`. It also runs `context_with_system` as the second phase of the request transform, after `context` and with the full transcript, and it emits `agent_start` and `turn_start` from the committed event stream, so the built-in Herdr and MCP integrations see a run start on this path: Herdr reports the pane as working, and MCP reconnects servers signed in to from outside the session when a turn starts. Herdr reports at all on this path now, because the extension sees `ctx.mode` as `tui` from `session_start` on instead of `print`.
- The default interactive and text print session paths now use the durable Harness and SQLite under `~/.nyan/agent/sessions-durable/`; `--continue` resumes the newest durable session for the current directory. Eligible `--mode json` and `--mode rpc` invocations now use durable storage and recovery. Legacy JSONL sessions selected through compatibility flags are opened read-only, so their source files are never migrated or appended to.
- `nyan login` and `nyan auth login` ask their questions on a terminal only. With piped or absent stdin they stop with instructions instead of waiting for input that cannot arrive.
- The `@ny4n/ai` development CLI (`npx @ny4n/ai login`) trims a typed answer, asks again when a choice is not one of the offered numbers instead of exiting with `Invalid selection`, and refuses an empty answer to a prompt that requires one.
- A request that fails certificate or host-name verification (an untrusted or self-signed certificate, an expired certificate, a certificate for another host name) is no longer retried, on Node and Bun alike. Node used to retry these failures, which repeated the same request with the same certificate. The error now names the certificate code in its message, for example `fetch failed (DEPTH_ZERO_SELF_SIGNED_CERT)`. To trust a private certificate authority, set `NODE_EXTRA_CA_CERTS` as before.
- Certificate failures whose URL contains text that resembles an HTTP status, such as `code500.example.com`, `?status=500`, or a path segment like `/status=500`, are no longer mistaken for retryable server errors. Bedrock errors with a provider prefix before a `503` status remain retryable.
- A model change on the durable path now reports `source: "cycle"` to `model_select` handlers when it came from `ctrl+p` or `shift+ctrl+p`, so an extension can tell a cycle from a picker or `/model`, which report `set`.
### Fixed

- On the default session path, a conversation made by `/fork` or `/clone` was labelled `subagent <id>` in the footer and in `/agents`, which read as a subagent's task. It is now `fork <id>`.
- The external editor (`ctrl+g`, and `externalEditor`) said `Pi will resume when the editor exits.` That line is shown by the default interactive mode and now names `nyan`.
- On the default session path, `--mode rpc` now binds its extension UI to every session it opens. After `new_session` and `switch_session`, an extension command read `ctx.hasUI === false`, and a dialog it opened was answered as if the user had cancelled it: the extension runner is built per open, and only the first one had the client's dialogs.
- On the default session path, `--mode rpc` now answers an extension dialog it is still waiting on when the session behind it is replaced (`new_session`) or switched (`switch_session`), or the client disconnects, instead of leaving the extension waiting on it for the rest of the run; the answer is the dialog's default, which is what a timeout gives, and that request id stops answering. A response whose shape answers a different dialog, such as a `confirmed` for a `select`, is refused with a failure whose `command` is `extension_ui_response` instead of being read as the dialog's own answer, and the dialog stays open for the answer it does ask for.
- When the GitHub CLI is not installed, `/share` reports that instead of telling the user to log in. A missing `gh` was reported as a failed login, which no `gh auth login` can fix.
- The built-in CLIProxyAPI extension no longer prints `[nyan-cliproxyapi] not configured` on every run. Users who do not use CLIProxyAPI saw it at startup of every mode, including a plain `nyan -p`. The extension is now silent until its provider is selected, where it reports the missing configuration once, and a `/cpa-*` command still says what to configure.
- `nyan --continue` in a directory without a durable session no longer ends with an uncaught `No durable session exists` exception and a stack trace. It continues the directory's newest durable session; a directory that has only legacy JSONL sessions reopens the newest of those read-only, with the notice a resumed legacy session prints; a directory with neither starts a new session, as 1.3.0 did.
- A durable session that cannot be started reports one `Error:` line instead of a stack trace: a session another process holds, a `--model` that names no available model, and `--api-key` without a model.
- On the default session path, a fork now runs the extension lifecycle the legacy path runs: `session_before_fork` first, which a handler can cancel, then `session_shutdown` with reason `fork`, then `session_start` with reason `fork` and `previousSessionFile` once the session talks to the new conversation. A durable fork is a new conversation inside the same session, so that file is the current one and the session id and file do not change.
- On the default session path, `ctx.sessionManager` kept reporting the previous conversation's entries after the session moved to a forked or subagent conversation. It now follows every switch.
- On the default session path, a prompt's `before_agent_start` message or system-prompt change could be missing from that prompt's first request when an `agent_end` handler of the previous run was still running: the new prompt's effects were queued behind the previous run's already applied ones. A run now clears its staged effects when it settles, before the settled handlers run.
- On the default session path, `--mode json` and `--mode rpc` now publish the event types the legacy path publishes. A `custom` entry a boundary handler appends, and a boundary `custom_message`, are reported as `entry_appended` instead of being dropped or appearing only as message events; a thinking-level change publishes `thinking_level_changed`; `set_session_name` publishes `session_info_changed`; `turn_end` carries the turn's `toolResults`, `tool_execution_update` carries the call's `args` and the output so far, and `tool_execution_end` carries `durationMs`; the entry a `bash` command records no longer appears as a user message. A `bash` command also emits the `user_bash` extension event first, so a handler's `operations` run the command instead of the local shell and a handler's `result` replaces the execution; a failed extension handler is published as `extension_error` with the same path, event, and message as legacy; a queue change is published as `queue_update` with the queued texts; and an answer that finishes within one partial interval publishes one `message_update` before its `message_end`. The remaining differences are listed under [Durable path](docs/json.md#durable-path).
- On the default session path, every extension handler that runs inside a run now reads `ctx.signal`. The `context`, `message_end`, `message_update`, `tool_call`, `tool_result`, `tool_execution_update`, `turn_end`, `agent_before_settle`, and `session_before_compact` handlers received `undefined` and so could not cooperate with an abort; `close()`, an abort, and a session switch now finish when such a handler waits for that signal. A handler that ignores it still holds those operations up, as it does on the legacy path.
- The durable TUI now shows a boundary `custom_message` entry as plain text with its custom type and keeps a `display: false` one hidden, instead of showing neither.
- On the default session path, `turn_end` and `agent_before_settle` handlers now receive the real session: `toolResults`, `toolResultEntryIds`, and the `context` preview were empty, and a `context_edit` that targeted a user or custom message was refused every time. Edits to those messages now take effect on the next request, and a handler that runs again after a crash before the boundary commit proposes the same entries, which are written once.
- Durable startup no longer reports the same invalid settings diagnostic more than once when the error is discovered through multiple settings sources.
- In the standalone executable on Windows, the process that closed a session no longer keeps the session database's `-shm` and `-wal` files locked, so the session directory can be deleted without leaving Nyan. Under Bun the durable session store now uses Bun's built-in SQLite (`bun:sqlite`) in place of `node:sqlite`; the file format is the same, and Node keeps `node:sqlite`.
- In the standalone executable, changing the HTTP idle timeout (`httpIdleTimeoutMs`, or the setting in `/settings`) while Nyan runs now also applies to provider clients that were created before the change. Before, such a client kept the timeout it was created with until Nyan restarted.
- A user ! bash command whose output is truncated returned the path of its full-output file before the file was completely written, so reading it at once could show a partial file. The path is now returned after the file is closed; if the file cannot be written, the output says so and the result has no path.
- `nyan auth check`, `nyan auth print-api-key`, `nyan auth print-bearer-token`, and `nyan login` reported every unexpected failure as `Failed to resolve credential`, hiding the cause. They now name the phase that failed and the error behind it.
- `nyan login` and `nyan auth login` substituted a prompt's placeholder for an empty answer. At CLIProxyAPI's API-key prompt this made an empty answer look like a real key, so the provider skipped its own empty-key check and sent the literal `sk-...` to the proxy, which failed with a misleading validation error instead of saying the key was empty. A placeholder is a hint, as it is in the interactive dialog, and an empty answer stays empty.
- `nyan login` and `nyan auth login` stopped with `Invalid selection` when a choice was not one of the offered numbers, and treated any answer other than `2` at the authentication-method prompt as OAuth. Both now re-ask.
- `nyan login` and `nyan auth login` announced `Successfully logged in` without checking that the credential works. They now verify it with the provider's own model listing, which authenticates with the credential just stored, and report a rejected credential as a failure with its reason. A listing that completes without the provider refusing the credential counts as verified; one that fails or is cancelled leaves the credential reported as stored and not verified.
- `nyan login` reported a provider whose model listing failed during the post-login credential synchronization as `Credential login committed for <provider>, but local synchronization failed`, naming neither the cause nor what to do. It now reports the provider's own error and says the credential is stored.
- The Xiaomi MiMo providers follow the rename of their models on models.dev (`mimo-v2.5-pro` to `mimo-v2.6-pro`). The built-in default model id and the tests that name it had gone stale, which left the provider without a usable default and the generated model catalogs unable to satisfy those ids.
- `nyan login cliproxyapi` verifies the key it just entered, not an environment key that would otherwise take precedence. A proxy that refuses the key fails the login, and the key stays stored to be corrected. A proxy that cannot be reached, or does not answer, leaves the key stored and reports it as not verified, instead of `Verified: 0 model(s) available`. Login warns when `CLIPROXYAPI_API_KEY`, the `apiKey` field of `cliproxyapi.json`, or `CLIPROXYAPI_BASE_URL` points the model list or requests somewhere other than what you entered. A key the proxy rejects at startup names the setting it came from. A failed verification says that the new login replaced the stored credential, which is not restored. `--method api_key` is refused with a pointer to the login that works.
- In the durable TUI, a `!` command whose `user_bash` handler threw left its card spinning `Running...` until the next entry arrived. The card is now removed and the failure is reported in the notice area with the handler's reason.
- `--provider` without `--model` on the default path reported `Error: Could not resolve model:` with nothing after the colon. It now prints the legacy path's `--provider requires --model (for example: --provider <name> --model <pattern>)`.
- On the default session path, an extension reading `ctx.sessionManager` saw a boundary `custom_message` as a plain user message, without its custom type, `display` flag, or details, and its projection carried that message as a user message rather than as the custom message the legacy path reports. Both now follow the legacy session entries.
- On the default session path, a batch of `agent_start` and `turn_start` events from the conversation a fork or a session switch moved away from could still reach extensions after the move. Only the conversation the session is on publishes, so the built-in Herdr and MCP integrations no longer see a start from a conversation that is no longer current.
- A host that embeds `main` (the SDK, and the experimental CLI that reuses it) is no longer exited when a durable session cannot be started: `main` prints the reason, sets the exit code, and returns, so the caller's process keeps running; `nyan` itself still leaves with the same code. A start-up diagnostic of type `info` no longer prints with a `Warning:` prefix.
- When a command's output could not be written to the full-output file in time, the file could be removed while it was still open, which on Windows left it in the temporary directory. The file is now removed only after the stream has released it, and the wait stays bounded.

## [1.3.0] - 2026-10-14

### Breaking Changes

- `before_agent_start` also runs for a run started by `nyan.sendMessage(..., { triggerTurn: true })`. `BeforeAgentStartEvent` is now a union on `messageType`: `"user"` carries `prompt` and `images`, `"custom"` carries the starting `message`. A handler that reads `event.prompt` or `event.images` must check `event.messageType` first, and a handler that adds context for a user prompt should return early for `"custom"`. The session also counts as busy while a run starts, so `ctx.isIdle()` is false during `before_agent_start`, and a message sent meanwhile goes into the starting run instead of starting a second one.
- `nyan mcp list --json` reports `"resources": true` for a server that offers resources, instead of the counts `resources` and `resourceTemplates`. Connecting no longer lists a server's resources, so a slow listing cannot keep its tools out of the first prompt. `/mcp` and `nyan mcp list` print `offers resources`. The resource tools still list and read resources on demand.

### Added

- Nyan reports its agent state to [Herdr](https://herdr.dev), a terminal workspace manager for coding agents, so a Nyan pane shows `working`, `blocked`, or `idle` in the Herdr sidebar, Herdr notifies you when Nyan finishes or needs input, and restarting the Herdr server reopens the pane in the same directory with the conversation restored. The integration is a built-in extension that acts only inside a Herdr pane. See [Run Nyan in Herdr](docs/herdr.md).
- The standalone executable archives and `SHA256SUMS` of a release carry a signed build provenance attestation. `gh attestation verify <archive> --repo blxzer77/nyan` shows that the file was built by the release workflow from a named commit. The executables are still not code-signed for macOS or Windows.
- Codemode tool declarations show input constraints such as `integer`, minimum and maximum, length, pattern, and `default` as `@` tags on property comments, so scripts see them without the tool repeating them in its description.
- Codemode rows show the time a script has been running while it runs and its total time when it finished, like bash rows.
- `describeNamespace()` and the `namespace` option of `searchTools()` in codemode scripts also match a namespace by its aliases. MCP namespaces answer to the server name, so `describeNamespace("docs")` finds `mcp__docs`.
- Tool definitions can declare `reachesTools`, for tools that reach other tools (such as `codemode` and `tool_search`). The MCP extension uses it to wait for the servers a call needs and to decide whether a replacement `codemode` or `tool_search` tool can reach MCP tools.

### Changed

- Print mode writes a warning to stderr and exits with status 1 when the final response stopped at the model's output token limit. The partial text is still written to stdout.
- Codemode declarations of MCP tools spell out the result type (`content`, `structuredContent`, `isError`) instead of referring to `CallToolResult<T>`, which `describeTool()`, `searchTools()`, and `ALL_TOOLS` showed without defining it. The codemode description no longer includes the shared MCP types.
- Compaction and branch summaries no longer include the model's thinking blocks. Replayed thinking is often not part of the live context, so including it could make a summarization request larger than the context it summarizes and fail.

### Fixed

- Stopping a codemode script or reaching its deadline no longer waits for a non-interruptible built-in to return on Bun. At most two codemode workers may be alive across all sessions in one process, and a cancelled worker keeps its slot until it exits; at capacity, a new script fails immediately.
- A resumed session restores the tools it had activated, with `--tools +name` and `-name` entries applied to them. Before, tools activated during the session were dropped. `--tools` with tool names, `--no-tools`, and `--no-builtin-tools` still select the tools explicitly.
- A leading `~` in exclusion and exact patterns of the `extensions`, `skills`, `prompts`, and `themes` settings (`!~/skills/pdf`, `-~/x`) means the home directory. Before, it was compared literally and never matched.
- On Windows, taking the `auth.json` lock retries briefly when a just-removed lock directory is still delete-pending and `mkdir` fails with `EPERM`. Real permission errors still fail at once.
- Terminal replies that arrive late, such as a device attributes or color report, stay out of keyboard input; the terminal keeps them until their terminator.
- Mouse wheel events that no component handles scroll the transcript under a focused overlay instead of reaching the overlay as raw input. An overlay that scrolls with the wheel must implement `handleMouse`.
- Kitty images are enabled in Herdr.
- Anthropic requests replace images in error tool results with a text note. The API rejects error results that contain anything but text, which stalled sessions after a failed codemode script that had shown images.
- Anthropic requests with strict tools retry with plain schemas when the API rejects the grammar (too large, too many strict tools, too many union types), and keep strict sampling for tools that require it.
- Tool call arguments with an invalid `\u` escape are repaired instead of failing the call.
- The wrapper text "The upstream provider returned an error" is retried like "Provider returned error".
- The OpenAI Codex request body is sent as a copy of the compressed bytes, which `fetch` accepts under every TypeScript lib.
- Codemode rejects a `// @options:` line that is not the first line of the script instead of ignoring it, which ran the script without its deadline.
- Codemode output with many text items is joined in linear time. A script that printed 100,000 empty lines took about ten seconds to format.

## [1.2.0] - 2026-10-12

Imports of `@earendil-works/pi-coding-agent`, `pi-tui`, `pi-ai` and `pi-agent-core` (and the same names under `@mariozechner/`) resolve to Nyan's host modules, and a package's `pi` manifest field is read when it has no `nyan` field. ### Fixed

- In the standalone executable (Bun), an extension is loaded from its source: its module code runs again on reload, and its imports of the host resolve to the running Nyan instead of a second copy that the runtime caches on its own.
- In the standalone executable (Bun), `--mode json`, `--mode rpc`, and print mode keep stdout for the protocol: output written with `console.log` goes to stderr there too, as it does on Node.
- In the standalone executable, `httpIdleTimeoutMs` takes effect. Before, a response that stalled before its headers or in the middle of its body was never given up on, whatever the setting. Proxy variables are read by Bun's fetch itself; the standalone executable now uses that fetch with an idle-timeout wrapper and no longer installs undici.

## [1.1.0] - 2026-10-12

## [1.0.0] - 2026-10-12

First release of Nyan, forked from [Pi](https://github.com/earendil-works/pi) v1.1.0 and synced with Pi up to commit `cdaf6c227`.

### Breaking Changes

- The executable is `nyan` and the package is `@ny4n/coding-agent`. There is no `pi` alias.
- Environment variables use the `NYAN_` prefix, the user directory is `~/.nyan/agent`, and the project directory is `.nyan/`. Nyan does not read `~/.pi`, `.pi/`, or `PI_*`, and does not migrate Pi's data.
- Nyan packages declare their resources under a `nyan` manifest field and use the `nyan-package` keyword. Extensions import `@ny4n/*`; the `@mariozechner/pi-*` and `@earendil-works/pi-*` import aliases for Pi extensions are gone.

### Changed

- Nyan makes no request to a hosted service unless the operator configures one. The installer, the `/share` viewer, the model catalog overlay, and MCP client metadata (`clientRegistration: "cimd"`) need `NYAN_INSTALLER_API_BASE`, `NYAN_SHARE_VIEWER_URL`, `NYAN_CATALOG_BASE_URL`, or `NYAN_MCP_CLIENT_METADATA_URL`; without them the feature is off or fails with an error that names the variable. Without a viewer, `/share` prints the gist URL only.
- The version check asks the npm registry for the `latest` dist-tag of `@ny4n/coding-agent`. `NYAN_LATEST_VERSION_URL` or `NYAN_NPM_REGISTRY` redirects it, and `NYAN_SKIP_VERSION_CHECK` or `NYAN_OFFLINE` turns it off.
- `/bug` writes a local zip file and uploads nothing.
- Settings, models, keybindings, and themes have JSON schemas in `schemas/`, usable for editor validation through `$schema`.

### Removed

- The Radius gateway: its provider, login flow, MCP offer, bug-report upload, and relay transport.
- The install-reporting ping and the `/dementedelves` announcement.
- The `doom-overlay` example extension.

### Fixed

- On Windows, resource patterns written by the configuration selector use `/`, so they match.
